# 草野球スコア記録

1試合分の打数・安打数を選手ごとに登録し、**打率（安打数 ÷ 打数）を自動計算して一覧表示**するWebアプリです。
入力方法は2モードあります。

- **合計入力（かんたん）**: 選手ごとの打数・安打数の合計をまとめて登録する最小版（`index.html`）
- **試合中入力（打席ごと）**: 試合の進行に合わせて、打者ごとに「打球方向・打球種類・結果」を記録し、正式ルールで打率を集計する発展版（`game.html`）

画面上部のタブで切り替えられます。

- 利用者: チームメンバー（自分含む）
- 技術: HTML / CSS / JavaScript（フレームワーク・サーバー不要。フィールド図はSVG）
- 保存: ブラウザの `localStorage`（このブラウザ内にのみ保存。ログイン・デバイス間同期はなし）

## 目的

草野球の試合結果を、いったんメモ用紙に記録してから改めてWebサイトへ転記しており、**同じ内容を二度入力する（二重入力）手間**が発生している。
このアプリで打数・安打数を**その場で1回だけ入力**すれば、打率まで自動計算されるようにして、転記作業をなくすことを目的とする。

## 使い方

### 合計入力（かんたん）— `index.html`

1. `index.html` をブラウザで開く
2. 「1. 入力」欄に **選手名・打数・安打数** を入力する（足りなければ「＋ 選手を追加」で行を増やす。複数選手をまとめて登録できる）
3. 「**登録して打率を計算**」ボタンを押す
4. 「2. 打率一覧」に、選手別の打率（小数点第3位まで）とチーム合計が表示される
5. 内容はブラウザに自動保存され、次に開いたときも復元される（消したいときは「**全データ消去**」）

### 試合中入力（打席ごと）— `game.html`

1. 上部タブの「試合中入力（打席ごと）」を開く（または `game.html` を直接開く）
2. 「1. 打順を登録」で選手名を入力して「**打順を登録**」を押す（記録するたびに次の打者へ自動で進む）
3. 打席ごとに「2. 打席を記録」で **① フィールドで打球方向をタップ → ② 打球の種類（ゴロ／フライ／ライナー） → ③ 結果** を選び、「**この打席を記録**」を押す
   - 三振・四球・死球・犠打は「打球なし」なので、方向・種類は不要（結果だけ選ぶ）
   - 間違えたら「**1つ戻す**」で直前の記録を取り消せる
4. 「3. 成績」に打席・打数・安打・打率などが自動集計される（四球・犠打は打数に数えない）
5. 「4. 打球方向マップ」に打球の飛んだ方向が色分け（緑=安打／橙=エラー／赤=アウト）で表示される

## 動作確認

### 合計入力（かんたん）

`index.html` をブラウザで開き、次の入力例で確認する。

| 選手名 | 打数 | 安打数 | 期待される打率 |
|--------|-----:|-------:|---------------:|
| 田中   | 10   | 3      | 0.300 |
| 佐藤   | 3    | 1      | 0.333 |
| 鈴木   | 4    | 0      | 0.000 |

- 「登録して打率を計算」を押すと、一覧が **佐藤 0.333 / 田中 0.300 / 鈴木 0.000**、チーム合計が **打数17・安打4・打率0.235** と表示される（確認済み）
- ブラウザを再読込しても、入力と一覧が保持される（確認済み）
- わざと「安打数 > 打数」を入力すると、エラーメッセージが出て登録されない（確認済み）
- 打数0の選手は打率が「----」と表示される（確認済み）

### 試合中入力（打席ごと）

打順に 田中・佐藤・鈴木 を登録し、次の9打席を順に記録する（自動送り）。

| 打者 | 記録内容 | 打数 | 安打 |
|------|----------|:---:|:---:|
| 田中 | 遊・ゴロ・安打 | ○ | ○ |
| 佐藤 | 中・フライ・本塁打 | ○ | ○ |
| 鈴木 | 遊・ゴロ・アウト | ○ | − |
| 田中 | 四球 | − | − |
| 佐藤 | 犠打 | − | − |
| 鈴木 | 左・ライナー・二塁打 | ○ | ○ |
| 田中 | 三・ゴロ・エラー出塁 | ○ | − |
| 佐藤 | 三振 | ○ | − |
| 鈴木 | 中・フライ・アウト | ○ | − |

- 成績が **田中 打率0.500（打数2・安打1）／佐藤 0.500（打数2・安打1・本1）／鈴木 0.333（打数3・安打1）**、チーム合計が **打数7・安打3・打率0.429** と表示される（確認済み）
  - 四球・犠打が打数に入らないこと、エラー出塁が打数だが安打でないことを手計算と照合して一致（検証②）
- 打球方向マップに、打球ありの6件が方向・色（緑=安打／橙=エラー／赤=アウト）で表示される（確認済み）
- 「1つ戻す」で直前の記録が取り消され、集計が戻る（確認済み）
- ブラウザを再読込しても、打順・記録・集計が保持される（確認済み）

## 検証

- **① 時間短縮（二重入力の削減）**: 「メモ用紙記入 → Webサイト転記」の所要時間と、本アプリへ「直接入力」する所要時間を計測して比較する。転記の一手間がなくなる分の短縮を確認する。
- **② 正しさ（手計算との照合）**: アプリが自動計算した打率を、手計算（安打数 ÷ 打数）の結果と照合する。合計入力では 3÷10=0.300、1÷3=0.333、0÷4=0.000、チーム 4÷17=0.235 と一致。試合中入力では、四球・犠打を打数から除く／エラー出塁を打数に含め安打から除く、という正式ルールを適用したうえで 田中1÷2=0.500・鈴木1÷3=0.333・チーム3÷7=0.429 と一致した。
- **③ 使いやすさ**: 試合中入力は「打者→方向→打球→結果」の順にタップするだけで、試合の進行と同時に記録できる（メモ用紙が不要になる）。
- **限界（まだできないこと）**: 現状は1試合分のみで、複数試合をまたいだ通算打率の集計はできない。走者の進塁・得点・イニングは記録しない。投手成績も対象外。データはこのブラウザ内にのみ保存されるため、別の端末とは共有できない。

## AI活用記録

AIに丸投げせず、出力を実行・確認して修正した記録。

- **依頼**: 「アプリ名・利用者・課題・技術・今日作る機能・入力・出力・保存・検証方法・今回作らない機能・完了条件」を指定し、最小構成のコード一式を依頼した。
- **打率の表示形式**: AIは打率を `0.333` 形式（小数点第3位）で出力。手計算（1÷3、3÷10 など）と照合して一致することを確認した。
- **打数0の扱い**: 打数0だと打率が計算できない（0で割ってしまう）ため、AIの案に対して「打数0のときは `----` と表示する」よう修正させた。
- **入力チェックの追加**: 空欄や「安打数 > 打数」といったありえない値でも壊れないよう、選手名必須・0以上の整数・安打数≦打数 のバリデーションを入れさせた。
- **範囲の確認**: 「今回は作らない機能（投手成績・ログイン・デバイス間同期）」を勝手に作っていないことを確認した。
- **試合中入力への発展**: 実際の使い方（試合中にその場で記録）に合わせ、フィールド図から打球方向を選ぶ打席ごと入力を追加依頼した。
- **打率ルールの指摘・修正**: 「セーフ/アウトだけ」では打率がずれる（四球・犠打は打数に数えない、エラー出塁は打数だが安打でない）ことを踏まえ、結果を正式ルールで分類するよう指示した。9打席の例を手計算（チーム 3÷7=0.429 など）と照合して一致を確認した。
- **表示バグの発見・修正**: 打球方向マップの点が守備位置マーカーの裏に隠れていたのを画面で確認し、マーカーの周りへ放射状に表示するよう直した。

## 実行方法

サーバーは不要。次のいずれかで開ける。

- **かんたん**: `index.html` をダブルクリックしてブラウザで開く（上部タブで `game.html` へ移動できる）
- **ローカルサーバー（任意）**: リポジトリのフォルダで以下を実行し、表示されたURLをブラウザで開く
  ```bash
  python3 -m http.server 8000
  # → ブラウザで http://localhost:8000/          （合計入力）
  #            http://localhost:8000/game.html  （試合中入力）
  ```

## 第12回の発展候補

- **複数試合の通算成績集計**（試合ごとに保存し、選手ごとに合算した通算打率を表示）
- **グラフ化**: 打球方向マップ（スプレーチャート）は実装済み。今後は試合ごとの打率推移を折れ線グラフにするなど。

> データ構造
> - 合計入力: `[{ name, atBats, hits }, ...]`（キー `kusayakyu_score_v1`）
> - 試合中入力: `{ lineup:[{id,name}], plays:[{batterId,result,ballType,position}], ... }`（キー `kusayakyu_game_v1`）
>
> 試合中入力は打席（plays）を1件ずつ持つため、試合単位でまとめて保存すれば、選手ごとの通算打率や打球方向の傾向へ素直に拡張できます。
